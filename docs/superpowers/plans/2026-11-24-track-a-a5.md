## Contract and choices

- Keep `warpPrevious(prev, cur)` and return new typed `color`, `lineMask`, `valid`
  buffers for the current dimensions. Invalid samples remain zero/invalid.
- Current pixel center `(x+.5,y+.5)` maps to previous center by subtracting
  `(motion.x*width,motion.y*height)`. Both captures have bottom-up rows.
- Reject nonfinite motion, nonpositive/nonfinite current depth, positions outside
  `[0,width) × [0,height)`, and history with different dimensions. Missing history
  yields an all-invalid result rather than treating arbitrary pixels as matched.
- Use a fixed 3% relative depth-consistency gate, as the starter's "few percent"
  heuristic. Require **every positive-weight depth tap** in the clamped bilinear
  footprint to be positive, finite and within 3% of current depth. An averaged
  depth can hide discontinuities; zero-weight taps must not reject a static match.
- Sample all RGBA channels and line coverage with the existing bilinear helper;
  reject nonfinite results. Do not mutate either capture or retain state.

The depth test is a heuristic: captured current/previous view-axis depths are in
different camera frames, so large dolly/rotation can reject valid history; distinct
objects at similar depth may pass. Motion XY alone cannot prove visibility or
recover expected previous depth. Keep the existing capture/pipeline contract.
Background is invalid by the starter contract, including hull-only background
pixels. A6 must report empty eligible line sets honestly, not invent zero stability.

## Decided during the build

Actual stationary Bunny capture showed maximum motion `3.5762787e-7` UV (~0.00023px
at 640px width), rejecting 24/42610 boundary pixels and slightly interpolating color
despite zero scene motion. Add a fixed per-axis 0.001px noise floor before mapping
to the previous image. A focused depth-boundary test failed without it; a separate
0.01px test preserves meaningful fractional motion. This is numeric stabilization
within A5, not a shared A1/pipeline change. Evidence: `static-precision-failure.log`
and `precision-red.log` in this session's verification directory.

The Measure integration test initially raced asynchronous download events, then used
an exact accessible name that did not match the folder's additional accessibility
label. It now clicks the observed button text and waits separately for both expected
CSV download events. No production UI code changed. The actual Static Run path exports

still placeholders. These exports are not final report measurements.
